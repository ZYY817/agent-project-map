# yq-map

**教 AI 给你的代码库维护一张准确的项目地图。**

yq-map 是一个 Markdown 文件——一份符合 [Agent Skills](https://github.com/anthropics/skills) 标准的说明书——教 AI 编程代理建立并维护一份轻量项目地图：几个 `MAP.md` 文件，记录东西在哪、彼此什么关系、每条信息可不可靠。有了它，AI 不用每个任务都把仓库从头翻一遍，直接落到相关代码上。

[English README](README.md)

## 它做什么

- **定位更快。** 每条带一个能搜的锚点——函数名、路由字符串、有辨识度的报错原文——让 AI 落在正确的代码行上，不只是正确的文件。
- **准确靠标注，不靠保证。** 每条都标 `已核对`、`推测`、`未知` 或 `已过期`，附核对日期——没核对过的信息永远装不成事实。
- **内置自检。** 锚点还搜得到吗？"已核对"被新改动推翻了吗？链接死了吗？可疑条目降级重查，不盲信。
- **更新跟着改动走。** 改了地图记着的文件，同一次顺手刷新受影响的条目，不搞单独的维护。
- **范围有边界。** 只画任务碰到的区域，没画的明说没画；已有文档链接不另抄，过期了标出来。
- **零依赖。** 没有服务器、索引器、数据库、运行时。只要 AI 会列、会搜、会读文件就能用——Claude Code、Codex、Cursor、Windsurf，或任何支持 skill 的工具。

## 带来的效果

- **少游荡，多干活。** AI 顺着地图直接找文件和符号，不再扫目录——上下文花在相关代码上，而不是花在探索上。
- **少走错路。** 过期和没核对的信息都标着状态，AI 先验证再信任，而不是自信地跟着旧信息跑偏。
- **理解能存下来。** 地图跨会话、跨任务有效——隔几天回来，不用重新付一遍探索的代价。
- **边界诚实。** 没画的地方明说没画，AI 说"我不知道"，而不是编一个答案。

## 安装

**当 skill**——把 `skill/yq-map/` 整个拷进工具的 skills 目录（比如 `~/.claude/skills/`、`.agents/skills/`）。放进去就能用。

**当规则**——把 `SKILL.zh-CN.md` 的正文贴进项目的 `AGENTS.md`（或 `CLAUDE.md`、`.cursorrules`）。不支持 skill 的工具也能用。

## 文件

```
skill/yq-map/
├── SKILL.md                      English
├── SKILL.zh-CN.md                中文版
└── references/
    ├── MAP.example.md            example map (EN)
    └── MAP.example.zh-CN.md      示例地图（中文）
```

## 一句备注

yq-map 是一套规矩，不是保证书——地图的准确度最终取决于执行它的 AI 模型的实际能力。状态标注的作用，是让这种依赖看得见，而不是藏起来。
