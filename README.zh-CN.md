# yq-map

**一张会承认自己在撒谎的项目地图。**

每个 AI 编程代理都在干同一件浪费的事：每个任务、每个会话，都把你的仓库从头翻一遍。常见的解法是记忆库或自动生成的代码地图——但它们有个致命缺陷：**从来没有人检查地图还是不是真话。** 代码天天在变，地图不会。六周后它还在自信地指向早已不存在的函数，而你的 AI 顺着它一头撞墙。

yq-map 就是一个 Markdown 文件——一份符合 [Agent Skills](https://github.com/anthropics/skills) 标准的说明书——教任何 AI 代理维护一张*诚实的*项目地图。

## 不一样在哪

- **状态必须标注。** 每条都标 `已核对`、`推测`、`未知` 或 `已过期`，附核对日期。一张不会说"我不知道"的地图，迟早会自信地说错话。
- **锚点，不是行号。** 每条带一个能搜的东西——函数名、路由字符串、有辨识度的报错原文——让 AI 直接落在正确的*代码行*上，不只是正确的文件。
- **有边界。** 只画任务碰到的区域，没覆盖的地方明说没覆盖。地图绝不装懂整个仓库。
- **自检内置。** 一套明确的核对流程：锚点还搜得到吗？"已核对"的条目被后来的改动推翻了吗？链接死了吗？谎话被降级，而不是被藏起来。
- **更新跟着改动走。** 改了地图记着的文件，就在同一次修改里顺手修受影响的条目。不搞单独的维护仪式。

## 零依赖

没有 MCP 服务、没有索引器、没有数据库、没有运行时。只要 AI 会列文件、会搜、会读，就能用——Claude Code、Codex、Cursor、Windsurf，或任何支持 skill 的工具。不用 skill？把规矩直接贴进 `AGENTS.md`，同一份文件，第二种装法。

## 真管用吗？

在一个真实的约 2000 文件的 React 项目上盲测过。从没见过这个仓库的 AI 代理：

- 建了一张限定范围的地图，复用了现有文档——并且**把过期的标了出来**
- 靠地图里一行"约束"直接定位到一个真实的渲染修复点，没有扫代码库
- 自检时抓到了一个埋进去的死引用，**外加地图里四处真错误**
- 重命名一个核心函数时，**在同一次修改里**更新了全部四个受影响的锚点——没有单独维护

诚实附注：规矩的效果取决于执行它的 AI——懒模型写出的地图也更糙。这算是我们给自己标的"推测"。

## 安装

**当 skill 装**——把 `skill/yq-map/` 整个拷进工具的 skills 目录（比如 `~/.claude/skills/`、`.agents/skills/`）。任务需要项目导航时 AI 会自动加载。

**当规则贴**——把 `SKILL.zh-CN.md` 的正文拷进项目的 `AGENTS.md`（或 `CLAUDE.md`、`.cursorrules`）。不支持 skill 的工具也能用。
